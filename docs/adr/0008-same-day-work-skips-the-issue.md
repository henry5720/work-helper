# 當天做得完的不開 issue

看完草稿之後兩條出口，**當場二選一，不留「之後再說」**：

| | 出口 |
| --- | --- |
| 今天之內一個 agent 做得完 | 直接派工吃草稿，做完 `slack-list ready`，草稿刪掉。**不開 issue** |
| 跨天、會換手、要跟你談 | 開 issue |

## 為什麼當天做完的不需要 issue

把 issue 買到的東西一項一項對照草稿檔 ＋ Slack item 留言串：

| issue 買到 | 草稿 ＋ Slack 串 |
| --- | --- |
| PM 看得到的介面 | ✅ 給得起，而且 issue 從來就沒在做這件事 —— `bin/slack-list` 整支沒提過 issue（ADR-0001） |
| 交接載體 | ✅ 給得起。agent 直接吃草稿檔，內容一模一樣 |
| slug 的來源 | 半 —— `fix/export-warehouse-only` 照樣開得了 worktree。掉的是 ADR-0002 那個碰撞偵測 |
| 三天後的紀錄 | 半 —— Slack 串活著（進度、驗收都在那）、commit 活著。掉的是「考慮過 B、為什麼排除」 |
| 去重指紋 | ❌ 給不起。`gh issue list --search` 搜的是 issue |

**只有三樣是 issue 獨有的：去重指紋、推導的長期存放、slug 的碰撞偵測。**
而這三樣有同一個條件 —— 指紋擋的是「下一輪偵察又查到同一列」、
推導要留是因為「談的人跟做的人不同或隔了幾天」、碰撞偵測擋的是「你忘了已經在做」。
**三個都只在事情沒有一口氣做完時才有價值。** 一口氣做完的，那三欄一個都沒被用到。

## 判準不是「行數多不多」

3 行的改動如果有取捨（「這個 race 我選擇加鎖不是重試」），commit message 裝不下那個取捨。
但這自洽：**有取捨 → 就要跟你談 → 談就跨天 → 落在開 issue 那一邊。**
所以按「跨不跨過今天」切，取捨會自動落到 issue，commit message 只需要裝
「當天做完、沒什麼好談」的那些 —— 那些它夠用（`skills/daily-worklog` 已經在從 commit 產日誌）。

## 升級規則

做到一半發現跨天了（要拆、PM 又補規格、你被叫去開會）——
**agent 就地把草稿當 body 開 issue，繼續做**，走「負責人發現新問題」那條路，不用新機制。

## 代價

你判斷「今天做得完」會判錯。判錯就是那件事在沒有 issue 的狀態下過夜，指紋沒埋，
隔天偵察可能重複開一次。升級規則救得回大部分，救不回「agent 死掉而你忘了」——
那時候 Slack 那列還在表上、狀態沒變成「PM確認中」，下次掃表看得到。

**草稿是消耗品，不是第二套 backlog。** 不刪的話 `drafts/` 會長成第二套 backlog，
那正是「不用建 `backlog/` 目錄」在防的事。
