# `⚠️` 的任務在 worktree 裡對齊，而且不換 agent

> ⚠️ **前提已被 [ADR-0013](./0013-alignment-replaces-plan-review.md) 修正**（2026-08-20）。
> 「不換 agent」的推導假設交接載體只能是 issue comment；handoff 檔帶得走推導，
> 所以結論縮小成「**別用 comment 換手**」。「對齊期間不准改檔案」那條不受影響。
> 另外：對齊現在是所有任務的預設，不只 `⚠️`。

偵察標 `⚠️` 表示「方向」那格空著 —— 兩種做法都合理，只有人挑得出來。
對齊那一格的談話**在 worktree 裡進行，談完的那個 agent 直接變負責人，一路做到底**。

## 為什麼不能換 agent

issue comment 帶得走「選了 A」，**帶不走「B 為什麼在第三輪被排除」** ——
而後者正是實作撞牆時要用的東西。換一個 agent 從 issue 讀，它拿到結論但拿不到那段推導。

所以 comment 還是要寫，但它的定位是**給三天後的你和 PM 看的備忘，不是交接文件**。
那個 agent 一旦 compact 到失憶，推導就是真的掉了，要重談 —— 這是接受的代價，不是漏洞。

## 兩種 `⚠️`，位置不同

| | 什麼情況 | 在哪談 |
| --- | --- | --- |
| **`⚠️ 範圍未定`** | 方向會改變**要開幾個任務**或**動到哪些檔案** | **發布前**，在 backlog 層。此刻還沒有 worktree 可開 |
| **`⚠️ 做法未定`** | 方向只改實作走法，範圍不變 | 帶著空格發布，接單後在 worktree 裡談，**跟「看計畫」合併成同一關** |

拆兩種的理由是 ADR-0002：**顆粒度必須在開 issue 那一刻決定，因為 issue 編號就是 slug。**
接單後才談，slug 已經定死了。偵察因此多判一件事：這個空格會不會動到範圍。

## 兩條防護

- **對齊期間不准改檔案。** 它坐在 worktree 裡，手會癢。
- **結論一定要 `gh issue comment` 回去**，即使它不是交接文件 —— 三天後回頭看只有 issue。

## 只有「方向」那格能空

現況空了 → 接單的人得重查一遍，偵察白做。
怎樣算解完空了 → 接單的人不知道什麼時候算做完，而且這欄一路流到 PM 驗收
（`bin/slack-list ready --verify` 用的是同一份）。
**前兩格沒填 = 沒交件，退回去查，不是 `⚠️`。**
偵察拿「不確定」當偷懶出口的話，每個都標 ⚠️ 等於沒有標，真正需要拍板的那幾件會被淹掉。

## 對齊一次只談一件

產出是**你的判斷品質**，那個東西平行不了。三個不相關的設計討論交錯著談，
你會忘記前面為什麼排除某個選項，然後在錯的前提上拍板。
