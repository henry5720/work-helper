# 偵察：查現況，開 issue，走人

**你是偵察，不是動工。** 這一輪的產出是**一批 issue**，不是一行 code。

一件事一個 worker，平行跑。說「分析」就會自己 fan out —— 不需要有人告訴你開幾個。

> 📁 **路徑假設**：`~/code/` 底下是兄弟目錄（`work-helper`、`work-docs`、各專案 repo）。
> 這台機器不是這樣擺的話 `ls ~/code` 看一眼，還是找不到就問使用者，不要猜。

---

## 每個 worker 做四件事

### 1. 讀目標 repo 的開單規範

照**你所在 repo 的 `CLAUDE.md` 觸發表**找到 issue 規範並讀完。issue body 長什麼樣由那份決定，不由這支 skill 決定。

**完成條件**：你講得出那份規範要求哪些欄位。講不出來就是還沒讀。

### 2. 查現況

grep、讀檔、必要時開自己的 worker 去別的 repo 查（**只帶結論回來，不要把對面的 repo 搬進 context**）。

**完成條件**：你手上有「要改哪些檔案」和「怎麼驗」。少任何一個就是還沒查完，回去查。

### 3. 查重，然後開 issue

```bash
gh issue list --search "<指紋或關鍵字>" --state all
```

命中就**不要開**，回報那張的編號。

⚠️ **只有 Slack 來源有指紋**（`Rec…` record_id，放 body 第一行、要看得見，不要藏在 HTML 註解裡）。PM 口述、順手發現的問題**沒有指紋** —— 那些要用關鍵字搜，而且要在回報裡說你搜了什麼。

沒命中才開：

```bash
gh issue create --title "..." --body-file ... --type <Bug|Feature|Task>
```

body 照步驟 1 那份規範，**外加三件**：

1. 指紋放第一行（如果有）
2. 最後一行自己標 `✅ 可以直接做` 或 `⚠️ 需要你對齊`
3. 標 `⚠️` 的要寫「考慮過的做法」和「我不確定的」

**完成條件**：issue 建立成功，而且裡面的每個路徑 `git cat-file -e origin/<主分支>:<path>` 過、每個識別字 grep 得到。錨點錯掉的 issue 跟程式碼寫錯同一個等級。

### 4. 交件，然後停

**`gh issue create` 成功之後就結束。回覆只給 issue 編號。**

標 `⚠️` 的多一步：把**推導**（考慮過 A/B、為什麼排除 A）`gh issue comment` 進去才算交件 —— 你交完就不在了，推導沒有第二次被問出來的機會。

**完成條件**：你的回覆是一行編號。不是簡報、不是摘要、不是「接下來我要…」。

---

## `✅` / `⚠️` 怎麼標

判準一句話：**答案在哪。**

| 查完之後 | 標 |
| --- | --- |
| 答案全在 repo 裡，改動點列得完 | `✅` |
| 有一件「使用者答了會改變做法」的事 | `⚠️`，並指名是哪一件 |

⚠️ **「我不確定的」只准放「答了會改變做法」的問題。** 「我沒去查後端」不算 —— 那叫還沒查完，回去查。

這個標籤是使用者唯一會 review 的東西。標錯了他馬上知道你沒搞懂，代價是兩分鐘；標對了他兩分鐘就能派工。

---

## Context 邊界：只拿 repo 外的東西

| | 拿不拿 |
| --- | --- |
| 模組路徑、相關檔案在哪 | ❌ repo 自己的 `CLAUDE.md` 就是地圖，自動載入 |
| 別的 repo 在哪 | ❌ 登記在 `~/code/CLAUDE.md` |
| PM 需求文件、prototype、UI 稿 | ✅ **repo 外的東西，只有這種要別人給** |
| 使用者猜問題在哪 | ❌ 那是你要查的，先接受會把你錨定在錯的地方 |

## 收工前：工作區要乾淨

N 個 worker 共用同一份 checkout，所以：

```bash
git -C <checkout> status --short
```

**空的才算收工。** 不是空的表示有 worker 越界動了檔案 —— 那段時間開的 issue，錨點要重驗（`file:line` 可能指向未提交的狀態），而且其他 worker 可能讀到改一半的檔案、寫出錯的結論。

⚠️ 這件事發生過：一個 worker 開完 issue 沒停，繼續改了 4 個檔案，而另外 4 個 worker 正在讀同一份工作區。

---

## 這一輪**不**做的事

- **不開 worktree、不開 branch。** worktree 要 branch 名 → 要 issue 編號 → issue 還沒開，是循環。
- **不實作。** 就算你已經知道怎麼改也不要動手 —— 實作走 `fleet-worktree`，在自己的 worktree 裡。
- **不 grill 使用者。** 有要人決定的事就標 `⚠️` 寫進 issue，然後交件。N 個 worker 每個都想討論，就是一整天沒了。
